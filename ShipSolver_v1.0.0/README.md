# ShipSolver v1.0.0 Stable

ShipSolver 是一个离线运行的舰船矩阵探测、记录、推算与存档工具。本版本是活动期间多轮迭代后的长期稳定版，版本号从试验阶段的 32.x/33.x 重置为正式发布版本 `v1.0.0 Stable`。

## 一、文件说明

压缩包中仅包含两个文件：

```text
ShipSolver/
├── index.html   # 工具本体，双击运行
└── README.md    # 完整说明文档
```

工具不需要安装，不需要联网，不依赖服务器，也不会把数据上传到外部网站。

## 二、运行方法

1. 解压压缩包。
2. 进入 `ShipSolver` 文件夹。
3. 使用最新版 Chrome 或 Edge 双击打开 `index.html`。
4. 建议浏览器缩放保持在 90%～110%。

若浏览器询问是否允许本地存储，请允许，否则自动保存和命名存档无法正常使用。

## 三、工具用途

工具主要用于：

- 记录棋盘中已知的“船”和“空”；
- 管理不同长度、不同数量的舰船配置；
- 根据当前事实排除不合法船位；
- 自动识别必然为船的位置；
- 计算可能区域和推荐大探测区域；
- 记录大探测批次、重复信息和冲突信息；
- 标记游戏中已经使用小探测确认的格子；
- 自动计算完成船只、剩余船型和锁定区域；
- 保存、读取、导入和导出盘面；
- 生成便于复制和复盘的摘要日志。

## 四、坐标规则

界面、日志和输入均从 1 开始计数：

```text
左上角为 (1,1)
右下角为 (行数,列数)
```

程序内部仍使用从 0 开始的数组，但用户不需要进行换算。

## 五、基本操作

### 1. 记录船

在未知格上单击左键，将该格记录为船。

### 2. 记录空

在未知格上单击右键，将该格记录为空。

### 3. 取消已有标记

按住 `Ctrl` 后点击已有格：

- `Ctrl + 左键`：取消已有船或空；
- `Ctrl + 右键`：同样可取消已有标记。

### 4. 选择船体

直接点击已经记录为船的格子，即可选择该格所在的整段连通船体。

不需要再次把该格标记为船，也不要求重复探测。

### 5. 确认整船

选择船体后点击“确认整船”。确认成功后：

- 该船计入完成进度；
- 周围八方向区域自动锁定；
- 推荐和剩余船型立即重新计算。

只有直线船体且长度存在于当前配置中，才能确认。

## 六、船只配置

顶部可以修改舰船长度和数量，例如：

```text
5×1
4×1
3×1
2×2
```

修改配置后，工具会重新计算：

- 完成船只；
- 剩余船只；
- 锁定区域；
- 合法船位；
- 推算结果；
- 大探测推荐区域。

不要把数量设置为 0 后保留无意义船型。删除不用的长度即可。

## 七、显示说明

### 已知船

红色格子，显示 `■`。

### 已知空

深色格子，显示 `·`。

### 锁定区域

灰色斜纹，显示正向 `×`。

锁定区域表示该位置受已完成船周围规则排除。后台可能知道该格为空，但界面统一显示为锁定，避免视觉混乱。

### 可能区域

黄色边框表示当前仍可能被合法船位覆盖。

### 必然为船

绿色边框表示该格在当前全部合法方案中均为船。工具可能自动将其记录为船，并在日志中说明。

### 推荐大探测区域

棋盘上会直接用颜色和边框标出推荐区域：

- 颜色越深，预计信息收益越高；
- 首选区域通常覆盖更多未知格、未完成船体附近位置和高价值候选船位；
- 最近反复探测、已经小探确认或已经锁定的位置会被降权；
- 每次修改盘面后都会重新计算。

文本区域同时显示推荐矩形的起止坐标、未知格数量、关联命中数量和近期重复权重。

## 八、大探测功能

大探测用于一次连续记录多个返回结果，并把这批信息作为一个事件保存。

### 操作流程

1. 点击“开始本次大探测”。
2. 在棋盘上连续录入结果：
   - 左键记录船；
   - 右键记录空。
3. 检查本次记录。
4. 点击“确认本次”写入历史，或点击“取消本次”放弃整批记录。

### 大探测期间纠错

- 再次点击本次已经录入的同一格，可取消该格；
- 点击顶部“撤销”，只撤销本次最后录入的一格；
- 不会跳回上次存档，也不会破坏已确认的大探测历史。

### 大探测统计

每个批次区分：

- 新增：以前未知、本次首次获得的信息；
- 重复：本次返回与工具中已有事实一致；
- 冲突：本次返回与工具当前事实不一致；
- 锁定冲突：返回船，但该位置已被完成船规则锁定。

冲突不会直接覆盖原事实，需要人工核对。

## 九、小探确认功能

“小探确认”不是推荐小探测点，而是记录游戏中哪些已知格已经通过小探测正式确认。

### 使用方法

1. 点击“✓ 小探确认：关”，切换为开启状态。
2. 点击已经记录为船或空的格子。
3. 格子右下角出现 `✓`。
4. 再次点击按钮关闭该模式。

### 作用

大探测规划会主动减少覆盖已经小探确认的格子，从而降低重复探测浪费。

小探确认不会改变格子的船/空事实，也不会单独决定船体是否完成。

## 十、推算逻辑

工具将棋盘事实与派生结果分开处理。

### 保存的事实

- 船；
- 空；
- 信息来源；
- 小探确认；
- 手动或自动确认的船体；
- 大探测事件。

### 实时派生的数据

- 船只完成进度；
- 锁定区域；
- 剩余船型；
- 合法船位；
- 必然为船；
- 可能区域；
- 推荐大探测区域。

派生数据不会作为绝对结果直接保存。读档、撤销、配置变化或船体变化后，系统会根据当前事实重新计算，避免旧进度和旧锁定残留。

## 十一、船只完成规则

船体在以下情况下可计为完成：

1. 用户选择船体并手动确认；
2. 船体长度符合配置，且两端由边界或已知空格封闭；
3. 系统根据合法方案确认其为唯一完整船体。

锁定区域本身不能反向证明船体已经完成，避免循环判定。

## 十二、推荐与概率说明

界面显示的推荐强度主要用于排序，不应一律理解为真实概率。

- “必然为船”代表当前全部合法方案都包含该格；
- 黄色可能区域代表至少存在合法方案覆盖；
- 推荐区域强度代表预计信息收益和探测优先级；
- 历史探测仅作为低权重参考，不会把某格直接判定为必然。

存在未完成命中船体时，推荐会优先关注相关延伸和附近区域，而不是被旧存档中的无关位置带偏。

## 十三、撤销与重做

### 普通状态

- 撤销：恢复上一步事实状态；
- 重做：恢复刚撤销的操作。

### 大探测进行中

- 撤销：只撤销本次最后一个格子；
- 再次点击同一格：取消本次该格记录；
- 取消本次：恢复到开始大探测前的状态。

## 十四、存档系统

### 自动保存

普通操作后会自动保存当前工作区。再次打开网页时会尝试恢复。

v1.0.0 可以读取并迁移以下旧版自动保存：

- 32.4.1；
- 32.4.0；
- 32.3.0；
- 32.2.0。

### 保存当前

当已经打开一个命名存档时，“保存当前”会覆盖该存档。

### 另存为

输入新名称后创建新的命名存档，不覆盖原存档。

### 导出和导入

- 导出当前：导出当前盘面 JSON；
- 导出全部：导出所有命名存档；
- 导入 JSON：读取以前导出的盘面或存档集合。

建议重要盘面同时导出 JSON 备份，不要只依赖浏览器本地存储。

## 十五、日志说明

日志以摘要为主，主要记录：

- 大探测批次；
- 自动推断；
- 整船确认；
- 完成进度变化；
- 存档操作；
- 冲突和异常。

日志不再强调每个无意义的界面动作，以免内容过长。

复制日志时会附带：

- 工具版本；
- 棋盘尺寸；
- 船只配置；
- 大探测批次摘要；
- 关键事件；
- 当前完成进度；
- 剩余船型；
- 当前推荐区域。

## 十六、完成后的行为

当全部舰船完成时：

- 推荐区域停止显示；
- 页面提示无需继续探测；
- 进度显示全部完成；
- 已有盘面、日志和存档仍可查看和导出。

## 十七、兼容性与数据迁移

- 命名存档继续使用原 `shipsolver_saves` 存储区，因此升级后可继续读取；
- v1.0.0 会尝试迁移近期旧版自动保存；
- 导入旧 JSON 时会读取主要字段并重新计算派生状态；
- 若极旧存档字段不完整，工具会尽量恢复棋盘事实，但部分日志或来源信息可能缺失。

## 十八、长期使用建议

1. 保留原始压缩包，不要直接覆盖。
2. 实际使用时解压到固定目录。
3. 重要盘面定期导出 JSON。
4. 不要同时在多个浏览器中编辑同一工作区。
5. 清除浏览器网站数据会删除本地存档，清理前应先导出。
6. 修改船只配置后检查完成进度是否符合当前游戏规则。
7. 若出现明显矛盾，优先检查是否误录船/空或导入了错误存档。
